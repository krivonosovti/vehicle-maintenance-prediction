# Vehicle Maintenance Prediction

**Учебный проект по машинному обучению — Центральный университет, осень 2026**

## О проекте

**Тема:** Прогнозирование вероятности возникновения неисправностей автомобилей на основе истории технического обслуживания.

Цель проекта — исследовать возможность применения методов машинного обучения для прогнозирования потребности автомобилей в техническом обслуживании и ремонте.

В рамках проекта мы анализируем характеристики транспортных средств, условия эксплуатации и историю обслуживания, выявляем закономерности и сравниваем различные алгоритмы машинного обучения.

## Постановка задачи

### Бизнес-задача

Разработать подход к прогнозированию потребности автомобилей в техническом обслуживании, который потенциально позволит автосервисам своевременно выявлять автомобили с повышенным риском неисправностей и формировать персонализированные рекомендации клиентам.

### ML-задача

На первом этапе решается задача **бинарной классификации** — прогнозирование вероятности необходимости технического обслуживания автомобиля.

**Целевая переменная:** `Maintenance_Required`

- `0` — техническое обслуживание не требуется;
- `1` — техническое обслуживание требуется.

В дальнейшем рассматривается возможность расширения решения до прогнозирования отдельных видов ремонта при наличии соответствующих данных.

## Датасет

**Источник:** [Logistics Vehicle Maintenance History Dataset](https://www.kaggle.com/datasets/datasetengineer/logistics-vehicle-maintenance-history-dataset)

По опубликованному описанию датасет содержит около 92 000 наблюдений и 27 столбцов.

Основные категории признаков:

- характеристики транспортного средства;
- возраст и интенсивность эксплуатации;
- состояние отдельных узлов автомобиля;
- условия эксплуатации;
- история технического обслуживания.

Перед обучением моделей необходимо проверить качество данных, определить доступность признаков на момент прогнозирования и исключить потенциальные утечки целевой переменной.

## Организация разработки

Работа команды организована через **GitHub Issues и Pull Requests**.

Каждая задача имеет уникальный идентификатор:

`VMP-XX | Название задачи`

Например: `VMP-01 | Создание и настройка GitHub-репозитория`.

Правила разработки:

1. Каждая задача оформляется отдельным Issue.
2. Для реализации создаётся отдельная ветка, например `feat/VMP-01`.
3. Изменения вносятся через Pull Request.
4. Перед объединением в `main` проводится Code Review.
5. Результаты экспериментов должны быть воспроизводимыми.
6. Все существенные выводы фиксируются в ноутбуках или отчётах.
